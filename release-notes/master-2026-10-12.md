OPM Flow for Windows, built from OPM master of 12 October 2026 — native MSVC build (hybrid MPI + OpenMP) with a Qt GUI workbench.

> **An unofficial build.** OPM Flow is developed by the [Open Porous Media initiative](https://opm-project.org). This is an independent Windows build of it, not a release of the OPM project, and OPM does not support it. Report anything wrong with *this package* here; anything you can also reproduce on Linux belongs upstream with OPM.

**A snapshot of OPM master, not an OPM release.** These packages are OPM master as of 12 October 2026 plus the Windows patches, and are named by that date. `flow --version` reports the development version master carried that day (2027.04-pre); that is OPM's label for master, not a version of these packages.

**Downloads** — the installer and the portable zip both work for most people; pick whichever you prefer. If you are on a **managed work laptop without administrator rights**, take the Intel MPI zip: it is the one that needs no administrator at any point.
- `OPM-Flow-master-2026-10-12-Setup.exe` — installer: adds Start-menu shortcuts, and installs over an earlier OPM Flow install (2026.10-pre included), keeping its saved GUI settings. It can install **for one user without administrator rights** as well as machine-wide, so it at least runs on a managed laptop. The Visual C++ and OpenMP runtimes ship inside the package, so the only external prerequisite is **Microsoft MPI** (the simulator links `msmpi.dll`); the installer installs it for you when run as an administrator. Installing MS-MPI itself always needs an administrator, so a per-user install ends by telling you that and how — if you cannot get one, use the Intel MPI zip below instead. The graphical front end is a component of its own: *Simulator only* installs just `flow.exe` and the runtimes it needs, for a cluster login node or a scripted install.
- `opm-flow-master-2026-10-12-win64.zip` — portable: unzip and run `bin\flow-gui.exe`. The Visual C++ and OpenMP runtimes are already in `bin\`; the only thing you might need is **Microsoft MPI** — if it isn't already installed, run `redist\msmpisetup.exe` once (or `winget install Microsoft.msmpi`).
- `opm-flow-master-2026-10-12-impi-win64.zip` — **the no-administrator option**, built against the Intel® MPI Library instead of MS-MPI. Unzip it anywhere you can write, then install the MPI runtime once *as yourself*:
  ```
  python -m pip install --user impi-rt
  ```
  That needs no administrator rights, where installing MS-MPI does — which is what otherwise blocks a locked-down machine, since the simulator links an MPI library even for serial runs. `flow-gui.exe` finds that runtime by itself; from a terminal use `bin\flow-impi.cmd DECK.DATA --output-dir=out`, or `bin\flow-impi.cmd -n 4 DECK.DATA ...` to run on 4 ranks. The MPI runtime is **not** bundled: OPM Flow is GPLv3 and Intel MPI is proprietary, so shipping them together raises a licensing question this package does not try to answer.
- `OPM-Flow-2026.10.12.0.msix` — unsigned MSIX (for sideloading/Store experiments; see PACKAGING.md); its version is the snapshot's date, since an MSIX version has to be numeric. **Note:** Windows will not enable its **Install** button unless the signing certificate is already trusted on the machine (it shows *"Publisher: Unknown / this app package's certificate could not be verified"*).
- No Linux package: on Linux, build flow-gui from source and bring your own `flow` — see the **Linux** section below.

**Contents:** `flow.exe` (all model variants, including black-oil; built from OPM master of 12 October 2026 plus the Windows patches) and `flow-gui.exe` **0.8.0** — a full workbench. New in 0.8.0: the **Compare** and **Well Hierarchy** tabs, arithmetic over summary vectors, a time span of your choosing, region arrays in the 3D view, text search, go-to-line and a region count in the deck editor, and case lists that keep up with a batch of runs. In full:
- **Fits a laptop screen.** The toolbars wrap onto further lines when the window is narrow, instead of demanding one fixed line: laid out that way they set a minimum window width of 2045 px — wider than a 1920 panel — so the window could not be sized to such a screen at all and *Maximise* had nowhere to go. Given the width they still lay out on one line exactly as before.
- **Full speed on modern laptops** — both `flow` and the simulators flow-gui spawns now opt out of Windows "EcoQoS" power throttling, which otherwise clocks background processes down dramatically (a serial Norne measured 1.6× slower without the exemption — including MPI ranks, which Windows always treats as background).
- **Run tab** — job queue with live progress/ETA, Stop/Skip, deck validation (`--enable-dry-run`), re-run of an already-finished queue (after confirmation), View PRT / View DBG / Open result folder, and a developer *Simulator* override to test your own `flow` build. *Run selected* runs only the highlighted decks instead of the whole queue, a **TUNING** checkbox passes `--enable-tuning` (off by default, matching flow's own default), and *Run*/*Validate* offer to save pending deck edits first, since flow re-reads the decks from disk. **View PRT / View DBG** show the report at the width it was written for — flow's lines run to 135 columns, and folding them broke up the very tables they line up into — with a *wrap* box for a long message, a search that names the file it is searching, and a window that remembers how you last sized it. Pressing *View PRT* again re-reads the report into the window already showing it, rather than stacking another, and that window can now be maximised.
  - **Parallel runs write to `<deck>_run_np<N>`**, so a parallel run no longer overwrites the serial one it is being checked against; one rank keeps the plain `<deck>_run`, so output already on disk is still found.
  - Beside *Simulator* is **when that executable was built**, turning amber past a month and kept current while the GUI is open — with several builds a pick away, a stale one otherwise looks exactly like a fresh one.
  - A deck already in the queue is **not queued twice** (both rows would write to the same folder), and each run opens the log with a dated banner instead of clearing it, since the log is the only record of a run that never started. A run's output is found even where flow upper-cases the case name (`CASE_water.DATA` writes `CASE_WATER.SMSPEC`).
- **Summary Plots tab** (renamed from *Results*) — summary-vector plotting straight from `SMSPEC`/`UNSMRY`: grouped/filtered vector picker with human-readable names plus qsummary-style **wildcard filtering** (`WBHP:B*, WOPR*`); click-to-focus **subplots**, each with its own vector selection; multi-case comparison with **renameable** cases whose new name drives the legend; calendar-date X axis by default; refresh-stable tree and zoom; CSV export. Plots refresh live while a run is still writing.
  - **Subplot grids up to 6×8, picked as a shape.** The *Layout* button opens a grid picker you hover to choose rows × columns, rather than a list of presets — a wide screen wants 2×5 or 3×6, and a list long enough to hold those is a list nobody reads. Charts are built as a layout asks for them, so a session that stays on one chart pays for one. Axes thin their tick count to whatever a subplot can label, so a dense grid stays readable instead of shrinking or eliding its labels.
  - **Ctrl+drag one subplot onto another to swap them** — vectors, zoom and legend position travel together, because where a plot sits in a figure is a presentation decision.
  - **Reset zoom, one subplot or all.** The button still clears every subplot; the arrow beside it clears just the focused one, so putting one plot back no longer costs the view on the others.
  - **A case list you can order**, since the list order *is* the plot order — of the curves, the colours and dashes keyed to them, the legend and the CSV columns.
  - **Sizes that follow the plot they are drawn in**: line width, marker size and legend text scale with the subplot, so a 2×2 layout no longer comes out as four crowded plots with a legend eating a third of each. Runs of the same deck are told apart by the part of their path that differs — **every** one of them, however they were loaded, so no case is left saying only the deck's name.
  - A vector with **no unit** — WMCTL's control-mode code, a count, a region number — gets an axis of its own titled *value*, instead of being dropped whenever something with a unit was selected alongside it.
  - A **Colour** box chooses what the curve colour separates, the *case* or the *vector*. Comparing two runs of one quantity, colouring by case is what tells the pair apart — and whichever dimension colour does not carry now takes the dash pattern *and* the marker shape, so no two curves share every channel.
  - Where **both Y axes cross zero** they share a grid, so there is one zero line rather than two at different heights, with every other gridline lining up and no data cut off.
  - Opening the tab on a restored session **opens the keyword groups holding what is plotted** and scrolls to them, rather than showing every group closed with the selection hidden inside.
  - **Auto-refresh does nothing** when nothing has been written since the last read, rather than re-reading and replotting every 10 s for a finished run. It also slows to 30 s and then 60 s while nothing changes and stops while the tab is not on screen, and snaps back to 10 s the moment a run writes.
  - **Arithmetic over vectors.** The *f(x)* box takes `+ - * /`, brackets, summary keys and numbers — `WBP:B-1H - WBHP:B-1H` for a drawdown, `FOPT/FGPT`, `WWCT:C-2H*100` — and the result is a curve like any other: it plots for every checked case that has its vectors, goes into the CSV and is saved with the project. Its unit is worked out (a difference of like things keeps their unit, a ratio of like things has none), and a division by zero leaves a gap rather than throwing the axis to infinity.
  - **A time span of your choosing.** *Span:* takes *whole run*, *common* — only the stretch every plotted case covers — or *custom* dates or days. Samples outside it are dropped, so the value axis rescales to what is left and a 30-day run is no longer drawn into a corner of a 130-day plot.
  - **Case lists that keep up with a batch of runs**: open several cases at once, tick and untick them in bulk from the *Check* menu (*Check selected only* plots just those), remove several at once or every unchecked one, and clearing the run queue takes its cases out of the list as well. Hovering a case gives its folder, its file and when it was last written; right-click opens or copies the folder.
  - **hide all-zero** drops the vectors that are zero at every step in every checked case — a fifth of the list on a big deck — and **Plot all listed** plots whatever a filter lists in one press. A pattern naming no item, such as `W*PR`, now matches the keyword.
  - Y axes **say what they carry** — `WOPR [SM3/DAY]`, not just the unit — and a nearly constant curve is drawn flat instead of as float32 noise filling the plot.
- **Publication-quality figures** — the legend docks to any edge, floats inside the plot (draggable with the mouse), or hides, and is set in bold a size above the axis labels with a line sample drawn heavier than the curve, so colour and case dash read at a glance; *Save figure...* writes a **vector PDF** sized to the figure (7 in wide, no margins, straight into `\includegraphics`) or a **300 dpi PNG** rendered at 3× rather than grabbed off the screen; colourblind-safe palette with round axis ticks, adjustable line width and marker size. Markers show **every data point** in the summary by default — nothing is sampled away, so they are exactly the samples the run wrote — with **hover** reporting the case, date and value; an *every n* box thins them on a dense curve, stepping by whole data points so a drawn marker is always a real `(time, value)` sample. A per-case shape and hollow fill (after the first case) keep curves separable where markers coincide, and with markers on the **legend shows them too** — each entry's sample is that case's shape riding on its line, so an entry looks like the curve it stands for.
- **3D View tab** — the corner-point grid colored by static (INIT) or dynamic (UNRST) properties incl. synthesized SOIL, well trajectories colored by type, and report-step animation with a **scrubbable** step bar: drag it, or click anywhere on it, to jump straight to that step. The orbit is unrestricted, so the model can be turned to show the base of the reservoir, with a *View* menu for Home / Top / Bottom / Side and an auto-framed default view. A *Remove* button drops a case from the list so it does not grow with every job of a long session (removing a case in the Summary Plots tab drops it here too). **Region arrays** — SATNUM, PVTNUM, EQLNUM, FIPNUM, EOSNUM, MPI_RANK — are drawn a colour per region with each region's cell count, and the *regions:* filter draws only chosen regions of any of them (`2`, or `1, 3-5`) whatever property is shown, with the colour scale taken over those cells alone. *fix range* holds the colour bar at the property's minimum and maximum over the whole run, or at ends you type.
- **Compare tab** (new) — do two runs agree, and if not, which property, from when, and by how much? Each restart cell field is reduced per report date to the cells outside tolerance, max |A−B| and RMS, using compareECL's own significance test, so a green verdict means what a green regression test means. Report steps are paired by **calendar date**, never by position in the file, so runs that report at different times are not compared at different moments. The **Overview** gives every property a small plot over the run — A solid, B dashed — that states how far apart the runs are as a share of A (`gap 1.5%`, amber past a percent) and keeps its axis open to a share of the property's own size, so agreement to five digits is drawn flat rather than magnified into alarm. **Cell values** shows one property at one date cell by cell — both runs, their difference, or A against B as a scatter about the diagonal — and **Cell history** follows one cell through time. Both read the restart files directly, with no Compare press, and clicking a point on the Overview aims them there: Cell history at the very cell the comparison found worst. The tables give the worst relative difference beside max |A−B|, and the tolerance boxes step by decade and accept a typed `1e-7`.
- **Deck Editor tab** — section tree over the deck and its INCLUDE files with Eclipse syntax highlighting. Sections **start closed**, so opening a deck shows its eight sections rather than a wall of hundreds of keywords, and a section you open stays open across a rescan instead of folding back up when a file changes on disk. Plus a keyword filter with expand/collapse, find & replace (*Replace all*, case sensitive by default), Undo/Redo, *Toggle comment* (Ctrl+/), reload of files changed outside the GUI, and double-click / right-click on an INCLUDE'd file name to open it; edits are saved to the original files, never a flattened copy. New: **text search** through the deck and its includes (switch the filter to *Text*), with the hits listed under the keyword each belongs to; **Go to line...** (Ctrl+G); and a **Regions** panel counting the region numbers the deck assigns to each set — SATNUM, PVTNUM, EQLNUM, FIPNUM and the FIPxxx sets, and the EOS regions of a compositional deck — beside the maximum TABDIMS, EQLDIMS or REGDIMS declares, in red where a number goes past it. It is read from the deck text, so a deck OPM cannot load yet is still counted.
- **Well Hierarchy tab** (new) — the shape of the field, read from the deck through opm-common's own parser rather than from any output: FIELD down through the groups to the wells, or the extended (`BRANPROP`) or standard (`GRUPNET`) network, at each date where it changes. Wells are coloured by what they do — producer, water, gas or other injector — in the tree and the drawing alike, the drawing follows opm-common's own graph conventions and exports to vector PDF or PNG with no Graphviz needed, and a *from:* picker draws one branch of a large field. Multisegment wells are marked in the tree with their segment count, and double-clicking a well opens **how it is put together**: its segments, the branch each is on and any valve, SICD or AICD it carries, and the connections with the deck's 1-based `(i,j,k)`, drawn the way opm-common's `plot_ms_wells` draws them. *Well hierarchy* on the Run tab opens a queued deck there, and a deck fenced with `SKIP100`/`SKIP300` is read the way `flow` reads it, or the way `flow_comp` does with *compositional* ticked.
- **Sessions and projects that come back** — a `.opmproj` file (and, with no project at all, simply closing the GUI) carries the whole working setup, not just the queue: the plotted **cases** and which one is **active**, the vector filters, **what each subplot shows** and how it is drawn (layout, legend placement including a dragged one, line width, markers), the **3D view**'s case and property, the **deck editor**'s open files, the front tab, the window geometry, and each finished job's output directory and outcome — so *View PRT* and *Open folder* still work on last week's runs. Starting flow-gui again picks up where the last session stopped; the 3D grid is only re-read once that tab is looked at, so it costs nothing at startup. Version 1 project files still open.

Fixed since 0.7.3: the GUI could open as a **blank white window** on a machine whose graphics driver lacks OpenGL 2.0 — the package now ships Qt's software renderer (`opengl32sw.dll`) for that case; opening or starting a project left the 3D and Compare tabs listing every case the session had seen; the summary tree called GPR and BPR "Average Reservoir Pressure", ignoring the keyword's scope (they are the group nodal pressure and a block's); a plot title counted a curve that had been left off for want of a free axis; and changing the date axis drew the new tick labels over the old ones.

Fixed earlier, from testing: the output-directory chooser could keep the *Directory:* box on the old name after a new folder was renamed, so *Choose* created a stray empty directory and used it for output; two runs of the same deck now **both** carry a tag saying which run they are, instead of only the second one being tagged; a run written to a **custom output directory** is no longer registered twice and listed under the same folder twice (it reached the GUI in native separators from there and with forward slashes from everywhere else, which compared as two different cases); the 3D step bar used to page towards a click instead of going there, and moving it while a static property was shown did nothing at all; and stepping through a run no longer grows without bound, since the restart reader caches every array it is asked for and cannot evict them one by one — its cache is now dropped wholesale once past a budget, which matters on models with millions of cells.

flow-gui is cross-platform: the same sources build on Windows, Linux and macOS, and on Linux you build it yourself, with the recipe below.

**Linux**

- **Bring your own simulator** — unlike the Windows packages, there is no `flow` for Linux here. Install or build OPM Flow following [opm-project.org](https://opm-project.org/?page_id=36) (e.g. the OPM binary packages: `sudo apt install mpi-default-bin opm-simulators`), then point the *Simulator:* field on the Run tab at it once (e.g. `/usr/bin/flow` or your own `.../opm-simulators/bin/flow`) — remembered between sessions.
- **Build flow-gui yourself** — it is a small standard CMake + Qt 6 project (Ubuntu shown):
  ```bash
  sudo apt install qt6-base-dev qt6-charts-dev libfmt-dev cmake ninja-build g++
  git clone https://github.com/GitPaean/opm_flow_windows
  cmake -S opm_flow_windows/flow-gui -B build-gui -DCMAKE_BUILD_TYPE=Release \
        -DFLOWGUI_OPM_PREFIX=<opm-common install prefix>
  cmake --build build-gui
  ```
  The Summary Plots, Compare, 3D View and Well Hierarchy tabs need an opm-common install prefix at configure time (watch for `flow-gui summary plotting: ON`, `3D viewer: ON` and `deck model (group tree / network): ON`); without it you still get the Run tab and deck editor. Full recipe including the opm-common step: [flow-gui/README.md → Building → Linux](https://github.com/GitPaean/opm_flow_windows/blob/master/flow-gui/README.md#linux).

**Getting past SmartScreen (this build is unsigned)**
The binaries are not code-signed, so Windows shows *reputation* warnings — these are not virus detections, and for the `.exe`/`.zip` they are dismissible:
- **When downloading** (Edge/Chrome): if it says *"… isn't commonly downloaded"* and the download stops or shows **Canceled**, open the download's **⋯ (More actions)** menu → **Keep**, then **Keep anyway**.
- **On first launch**: if *"Windows protected your PC"* appears, click **More info → Run anyway**.

**Notes**
- Windows 10/11 x64.
- Parallel runs, MS-MPI package: `mpiexec -n <ranks> flow.exe DECK.DATA --threads-per-process=<threads> --output-dir=<dir>`, or use the GUI.
- Parallel runs, **Intel MPI package**: use `bin\flow-impi.cmd -n <ranks> DECK.DATA ...`, or the GUI. Not a bare `mpiexec` — if MS-MPI is also installed that name resolves to *its* launcher, which cannot start an Intel MPI binary and fails with `unable to decode hostport …  PMI_Init returned -1`. `flow-impi.cmd` and the GUI both pick the right launcher for you.
